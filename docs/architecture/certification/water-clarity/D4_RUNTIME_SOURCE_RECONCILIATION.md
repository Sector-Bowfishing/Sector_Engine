# Clarity D4 — runtime-source reconciliation (RA-18)

**Scope:** make the source that actually produced the live Clarity Cloud Run runtimes durable and canonical on `main`, with ancestry, **without** bringing research, data corpora or private detail into the tree. No deploy, no scheduler change, no RTDB/`sector-brain` write. This PR does not certify anything and does not create `brains/water-clarity/`.

## 1. Method
`git merge --no-ff feat/clarity-algal-warning` (tip `03937913cd9c207c5f73a3dbbaaa430d74e7a903`; merge-base with main `be1d8932`, which is already on main). Ancestry of all 18 branch commits is preserved. The **tree** was then restricted to runtime source (§3); excluded paths are not in the tree but remain reachable through the branch and are intentionally not adopted here. Three textual conflicts were resolved additively (`Package.swift`, `Dockerfile`: union of main's `WaterTempBrainJob`/`LakeBrainJob` with `ClarityPrecompute`; `deploy.sh`: main's live sizing kept, the Linux smoke gate from the branch added). No code was cherry-picked or rewritten.

## 2. Build provenance of the live Clarity runtimes (read-only: Cloud Build, Artifact Registry, Cloud Run, and a byte-level comparison of the deployed source archives; 2026-10-17)
All five were built by `gcloud … --source` (Cloud Run source deploy) from an **uploaded working-tree zip**. Cloud Build records the zip, never a git commit, so no build records a commit by itself. The four small archives were downloaded read-only (their MD5 equals the Cloud Build record) and every file was compared byte-for-byte (git blob hash) against the Git trees of all candidate commits. Result classes: `EXACT_MATCH` = every uploaded file is byte-identical to the named commit's tree (files staged by the job's `deploy-job.sh` from other repo paths were verified against their sources); `MATCH_EXCEPT_BUILD_METADATA` = same, plus compiled `.pyc` caches and staged copies that are not tracked at that path. Nothing is inferred from timestamps where the comparison answers.

## 3. Included in the tree
`Package.swift`, `Dockerfile`, `deploy.sh`, `scripts/linux-smoke.sh`; `Sources/ClarityPrecompute`, `Sources/SectorEngine/Clarity/*`, `Sources/SectorEngine/API/CurrentClarityAPI.swift`, the modified `ClarityState*`/`VisibilityModel`/`SectorEngineServer`/`ClarityReplay` sources; `Tests/` (Algal, CurrentClarity, PreparedClarity, ClarityState); `jobs/lake-surface/*` (live `daily.py`, `derive_water_surface.py`, deploy files); `jobs/clarity-current/deploy-job.sh`; `scripts/hydrology/{current_cells,arm_anchor}.py` and the two small runtime region inputs `docs/data/hydrology/guntersville/guntersville.current_regions.{bin,json}` (the lake-surface `deploy-job.sh` copies these into the image).

## 4. Deliberately excluded from the tree (present only in the merged ancestry)
`docs/data/hydrology/**` other than the two runtime region files (≈ 850 research/replay/evidence files, ~20 MB incl. the 12 MB `clarity_evidence` JSON); `docs/clarity/**` (stage handoffs, preregistrations, 28 screenshots); the stage-analysis scripts under `scripts/hydrology/` (replay, skill, zone, stage3b, …). Never merged: `feat/clarity-candidate-shadow`, `research/clarity-candidate` (14k–17.8k research files, PDFs, private evidence), `jobs/clarity-candidate`.

## 5. Consequences and limits
- Merge ancestry carries the branch's research blobs (~24 MB) into main's **history**, although not its tree; those blobs are already public via `origin/feat/clarity-algal-warning`.
- The Swift Linux image was **not** rebuilt or deployed; a local `swift build`/`test` result is recorded in the PR. Redeploy remains a separate, approved task, and `LINEAGE.md` stays as the warning until the deployed images are rebuilt from main.
- This does not establish that the live images are byte-reproducible from these commits (see confidence column).
