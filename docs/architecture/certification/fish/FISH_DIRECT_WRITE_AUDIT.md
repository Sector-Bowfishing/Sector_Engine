# Fish direct-write audit

Scope: every Fish/Biological runtime path (`brains/fish/runtime/**`, and the pre-move `jobs/biological-brain/**` at `main` and on the adoption branch). Method: AST scan of call sites named `update/put/patch/post/set/delete`, import scan (`firebase_admin`, `requests`, `google.cloud`), scan for REST `method=` PATCH/PUT/POST/DELETE, and a manual read of `run.py`, `run_state.py`, `tools/*.py`. Enforced by `tests/test_fish_certification.py::test_no_unauthorized_production_write_in_the_fish_runtime` (the set of database write sites must equal exactly the row below).

| # | Site | What it does | Classification | Notes |
|---|---|---|---|---|
| 1 | `runtime/run.py` `rtdb.update(updates)` (`--write`) | one atomic multi-path update to the Brain RTDB through `sector_brain_platform.BrainRtdb`, ownership-checked (`ownership.assert_owned`), refuses app/customer databases | **LEGACY** → `RETIREMENT_CANDIDATE` at the Publisher cutover | The orchestrator starts it in-process (`run.py --write`) when `plan()` says PUBLISH. It is the only production write door Fish has. Not changed here (behaviour-neutral); the Publisher path exists beside it in shadow. Retirement gate: Publisher production enablement + approved cutover plan (not started). |
| 2 | `runtime/run.py` `--dry-run` artifact path (`build_artifact` + in-memory `local_shadow_stack`) | builds/evaluates the artifact in memory; writes only local files (`updates.json`, `artifact.json`) | **SHADOW_ONLY** | `PublisherMode` has no live member; the shadow sink counts `live_mutations == 0` (tested). |
| 3 | `runtime/run_state.py` | Biological State pilot: `BrainRtdb` used with GET only; writes a local JSON file | **SHADOW_ONLY** (internal, unscheduled) | Recorder attached; `consumed` printed. |
| 4 | `runtime/tools/*.py` (`stage_bundle`, `adopt_cards`, `review`, `observations`, `gen_schemas`) | local file writes to paths given on the command line (bundle staging, research intake) | **SHADOW_ONLY** (no database client; no network) | `stage_bundle` writes a local staging directory; uploading to the private bucket is a manual operator step outside the repo. |
| 5 | `runtime/run.py` `gcs_reader` | authenticated **read** of the private bucket | n/a (read) | Own knowledge release; recorded as artifact lineage, not `consumed[]`. |
| — | any Firebase Admin / REST PATCH-PUT-POST-DELETE / production DB helper / legacy publication code | none found | — | Scans return nothing else. |

**Result:** no `BLOCKER`. Production-write ownership is unambiguous: *Fish specialist runtime produces domain truth and (shadow) artifact; the Publisher is the intended only production door; the single legacy door (row 1) is explicitly classified and gated.* Invariant 10 of `tools/architecture/report.py` ("no direct specialist production writer after that Brain's Publisher cutover") passes because Fish's `publisherRequired.cutoverStatus` is `SHADOW`, not `CUTOVER_COMPLETE`; it will fail by design the moment the cutover is declared while row 1 still exists.
