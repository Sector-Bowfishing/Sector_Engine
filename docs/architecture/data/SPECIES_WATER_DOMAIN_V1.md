# Species Water Domain Metadata V1

**Rule: the Engine owns the truth, Ops owns the presentation.**

## Why it exists
Sector Ops lists Fish Brain species but could not say whether a species lives in fresh, brackish or salt water. That is species *identity* metadata. It belongs to the Species Registry, not to Ops, and not to any Brain's scoring.

## Owner and schema
Owner: **Species Registry** (`platform/registries/species/`). Authority: `platform/registries/species/species_water_domains.json`, schema `contracts/schemas/registry-species-water-domains.schema.json`.

```jsonc
{ "speciesId": "common_carp", "commonName": "Common carp",
  "waterDomains": ["FRESHWATER", "BRACKISH"],          // or null when UNKNOWN
  "assessment": { "status": "ASSESSED",                 // ASSESSED | UNKNOWN
                  "confidence": "MEDIUM",               // HIGH | MEDIUM | LOW | null
                  "basis": "REFERENCE_DATABASE",        // REFERENCE_DATABASE | MEMBER_UNION | NOT_ASSESSABLE
                  "sources": [{ "sourceId": "FISHBASE_SPECIES_SUMMARY", "reference": "Cyprinus carpio", "url": "…", "retrieved": "2026-10-19", "statement": "Freshwater; brackish" }],
                  "reviewRequired": false } }
```

## Enum semantics
`FRESHWATER`, `BRACKISH`, `MARINE`: the environments the species is recorded as occurring in, at species level. Array, one to three values, canonical order (FRESHWATER, BRACKISH, MARINE), no duplicates, never free text. Internal name is `MARINE` (biologically clean; matches the earlier design's `marine` index); Ops renders it as **Saltwater**.

## Multi-domain behavior
A species carries every applicable value and appears under every matching Ops filter. No life-stage model. Where a species-level value cannot be stated truthfully the value is **UNKNOWN**: `waterDomains: null`, `status: UNKNOWN`. Unknown is never defaulted to freshwater.

## What it does NOT mean
- **Water domain is not a life-history/migration strategy.** `DIADROMOUS`, `ANADROMOUS`, `CATADROMOUS`, `POTAMODROMOUS` are never values here. American shad and striped mullet are diadromous and simply list every environment they use.
- Not legality, policy, per-lake presence, abundance, target role, or a research score input. No Brain score reads it.
- Not a Brain split: Fish Brain (`biological-state`) stays one Brain.
- Not a rename or taxonomy cleanup.

## Fish release interaction
Species Registry = identity (single authority). The Fish release carries a **deterministic projection** because the orchestrator image ships only `runtime` + `platform`: `brains/fish/runtime/water_domain_registry.py` is generated by `runtime/tools/gen_water_domain_projection.py` and tests assert it equals the registry file. `species_summary` adds `waterDomains` (absent when UNKNOWN) and `waterDomainStatus` for registered species. Never edit the projection by hand; regenerate it.

## Ops presentation contract
Ops reads `/species/{id}.waterDomains` and `.waterDomainStatus` only. Labels FRESHWATER→Freshwater, BRACKISH→Brackish, MARINE→Saltwater; absent/UNKNOWN → "—"; filters All/Freshwater/Brackish/Saltwater, multi-domain under each. Ops keeps no classification map.

## Future saltwater
Adding species is a registry row. No enum, schema, path or id change; Fish scoring is untouched.

## Provenance and limits
Backfill basis for 27 species is the FishBase species summary "Ecology" environment line, retrieved 2026-10-19 (single secondary reference; confidence MEDIUM, HIGH where it agrees with the existing Sector evidence packet). Five rows are `reviewRequired`: gizzard shad (MARINE flag), shorthead redhorse (BRACKISH flag), and the three grouped/unresolved rows (`carpsuckers_group`, `tilapia_unresolved`, `suckers_redhorse_carpsuckers_group`). The last is UNKNOWN. A primary-source (USGS/state) pass would raise confidence; it is not a blocker.
