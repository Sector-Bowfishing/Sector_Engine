# Lake Brain: level-source provider adapters

Status: implemented and exercised read-only against live data on 2026-10-13. Nothing here publishes to any RTDB or bucket; the live
exercise used `LakeBrainJob --dry-run DIR --include-candidates`, which writes local files only.
Code: `brains/lake/runtime/LakeBrain/LakeLevelFeeds.swift` (TVA, CWMS, USGS live), `LakeLevelFeedsFleet.swift` (Access2Water, RISE, NWPS, HADS, USGS history) and `LakeLevelFeedsHydromet.swift` (Reclamation Hydromet, section 4).
Bindings: `docs/brains/LAKE_BRAIN_INTEGRATION.md` section 5.

Unknown (outside NWS coverage, outage) is treated conservatively |

All requests use `Sector-LakeBrain/1.0 (io.sector.co; read-only public data; contact ...)`, a 120 s read timeout (the engine's 8 s cap is for request-path fetches; a HADS chunk or an Access2Water listing is bigger) and never write anything.
Not implemented: **TWDB** (no strict-verified lake uses it), **CO-OPS** (Great Lakes harbours only, not on the allow-list) and **NWRFC** (section 4).

## 2. Traps the adapters enforce

| Trap | Handling |
|---|---|
| USGS `00065` is a gage height in a local datum, not an elevation | refused as a live series; as a history only with an explicit datum offset (gage height + site altitude, Lake Winnebago) |
| USGS `-999999` no-data sentinel (a sensor outage today at Buckeye Lake) | dropped; the lake falls back and says so (`primarySourceStale`, `fallbackSource`) |
| CWMS defaults to SI units | requested with `unit=EN`; a response that still says metres is multiplied by 3.28084 |
| CWMS dense series (15 min) overflow the page budget | request window shrinks with the series interval (5 years daily/hourly, about 1 year at 15 min); hitting the 20-page limit is an error, never a silent truncation |
| Sub-daily history series | reduced to the median of each lake-local day (identical to the reading itself for a daily series) |
| Access2Water plain `Elev` on tailwater locations looks like a pool | bindings carry the exact tsid; the tailwater sibling is a different tsid and is never read |
| Access2Water is latest-only | the reading is the latest value and, from `delta24hr`, the value 24 h earlier: enough for the 24 h trend, 1 h / 6 h / 3 d / 7 d changes stay unknown |
| RISE writes 0.0 for a missing day; results can be modeled | `result <= 0` and any `resultType` other than `observed` dropped; the history day is the UTC date of the stamp (as in the research) |
| NWPS `HG` stage vs `HP` pool; `-999` sentinels; flow units | the gauge's `pedts` must start with the binding's pe code; units must be ft; sentinels dropped |
| IEM HADS rate limit (HTTP 429 above about one request per 15 s) | one process-wide gate (15 s between requests), 3-year chunks newest first, 429 backs off 60 s and doubles; any failed chunk fails the whole pull (no silent hole), the walk stops at the first empty chunk |
| Hydromet `AF` is storage (acre-feet), `GH` a gage height, `Q` a flow | only `FB` (reservoir water surface elevation) is read; any other parameter is refused before a request, and an answer without the `SITE FB` column fails as a whole |
| Hydromet `998877` missing value is a number; `MISSING` / `NO RECORD` / blank cells | dropped, with values <= 0; a day with no reading stays missing |
| Hydromet stamps have no offset and a region spans time zones | read as the site's wall-clock time in the zone named by the binding (`REGION:SITE:Area/City`); a live binding without a zone fails closed. Daily `FB` rows keep the date in their stamp |
| A research history that is a different series from the live level | every run compares the median of the seeded history of the last 365 days with the live level; more than 15 ft sets `historyLiveMismatch:<delta>ft` and an error. The 14 lakes the rules-v2 QA found are held out of the table |

What the exercise found and fixed:
- **HADS multi-column archive (bug, fixed):** the first run of the two NWPS lakes read only the first `HPIR…` column of each 3-year chunk and lost 2021-10 .. 2023 (Canton 12 y, Lewis and Clark 3.4 y, INSUFFICIENT). A gauge can move its pool between `HPIRGZZ` and `HPIRZZZ`; the parser now takes the first non-empty `HPIR…` column per row (unit test added). Re-run: 15 y and 6 y, matching the research counts.
- **RISE host outage:** `data.usbr.gov` timed out for several minutes during the first attempt (curl too). The adapter returned an error, the run degraded to the verified NWPS fallback and said so (`sourceError`, `primarySourceStale`, `fallbackSource`, a history error); the re-run a few minutes later was clean.
- **Guide series that stopped:** the research catalog lists CWMS `Elev-Guide Curve` series whose extent ended in 2021 or 2022 (Lake Martin `1Hour`, Okatibbee). Only series whose catalog extent reaches today are claimed: Okatibbee and Wappapello lose their guide evidence, and Lake Martin uses the live `15Minutes` series.
- A2W lakes at LRL / MVP report 20 to 25 h old (Brookville, Barren River, Cave Run, ...): inside the research window (R6, 72 h) but beyond the 5 h stale threshold, so those candidates will run as `sourceStale` until the district feed catches up.
- No full fleet run was made; about 20 requests per host per lake at most, HADS at one request per 15 s.

Reproduce one lake (local files only): `swift build --product LakeBrainJob && .build/debug/LakeBrainJob --dry-run /tmp/lb --include-candidates --lake "Canton Lake|OK"`.


## 4. Pacific Northwest and Great Plains readers (Reclamation Hydromet, NWRFC, CWMS NWDP / NWDM)

Added 2026-11-22 (owner decision, chat 2026-11-22: build readers for lakes that passed the binding checks but need a reader the Engine does not have). **Reader only:** no lake is bound to Hydromet (`LakeBrainHydrometTests.testNoLakeIsBoundToHydromet`). Binding a lake goes through the acceptance gate like every other binding (`LAKE_BRAIN_BINDING_REVIEW_PROTOCOL.md`); `usbr-pnhm` is not on the bindings-table allow-list (`jobs/lake-brain/bindings/build_bindings_table.py`; Banks Lake, Crescent Lake, Lake Cascade and Potholes Reservoir are excluded as `provider-not-allowed`, and as post-hoc wave rows).

### Reclamation Hydromet (`hydromet`)
- **Source.** Bureau of Reclamation regional Hydromet networks: Pacific Northwest (`/pn-bin/`, Columbia and Snake basins: Grand Coulee, Banks Lake, Potholes, Cascade, Anderson Ranch, Palisades, ...) and Great Plains / Missouri Basin (`/gp-bin/`: Canyon Ferry, Tiber, Pueblo, ...). RISE (`rise`) carries daily values for many of these reservoirs, but not every Pacific Northwest one, and only daily with about 48 h latency; Hydromet is the region's own 15-minute record. No authentication; no published rate limit.
- **Endpoints.** PN instant `instant.pl?list={SITE}%20FB&back={hours}&format=csv&flags=false&description=false`; PN daily `daily.pl?station={SITE}&format=csv&year=&month=&day=&year=&month=&day=&pcode=FB` (start date, then end date, in that order); GP instant `webdaycsv.pl?parameter={SITE}%20FB&syer=&smnth=&sdy=&eyer=&emnth=&edy=&format=2`; GP daily `webarccsv.pl?…&format=2` (same parameters, in that order). Sources: Reclamation's Hydromet pages (`usbr.gov/pn/hydromet/realtime.html` links `instant.pl?list=…&back=…`), the GP "Automated Retrieval Documentation" (`usbr.gov/gp/hydromet/automated_retrieval.pdf`), and published clients (`daily.pl?station=…&year=…&pcode=…`; `{region}-bin/webarccsv.pl` read between `BEGIN DATA` / `END DATA`).
- **Answer.** Comma-separated text; a header whose first column is the date and one column per `SITE PCODE` (matched ignoring case, spaces and `_`), optionally inside HTML and (GP) between `BEGIN DATA` / `END DATA`. Stamps `MM/dd/yyyy[ HH:mm]` or `yyyy-MM-dd[ HH:mm]`; hour 24 is the midnight that ends the day.
- **Binding shape.** Live: `provider: hydromet`, `station` = `REGION:SITE:Area/City` (e.g. `PN:MLAW:America/Los_Angeles`, `GP:CAFE:America/Denver`), `series` = `FB`; `sourceId` `hydromet:{REGION}:{SITE}:FB` (the zone is configuration, not identity). History: `hydrometDaily(region, site, param, offsetFt)`, in the generated table `{"kind": "hydrometDaily", "region", "site", "param", "offsetFt"}`.
- **Parameter.** `FB` (reservoir water surface / forebay elevation, ft) only. `AF` storage, `GH` gage height and `Q` flow are refused before any request.
- **Time zone.** Hydromet stamps are the site's local wall-clock time without an offset (Hydromet's `dfcgi` documentation). PN spans Pacific and Mountain time and GP Mountain and Central, so the zone is part of the live binding and a live binding without one fails closed. Whether a site stamps daylight time in summer is not documented: confirm on the first live probe (compare a summer stamp with the same reading on the site's Hydromet page) before binding a lake. If a site stamps standard time all year, summer readings are read one hour **older** than they are, never fresher.
- **History.** Daily `FB` is the midnight reading of the day it is dated; the history day is the date in the stamp. Pulled newest first in 10-year windows, one request at a time; two empty windows end the walk, any failed window fails the whole pull. A daily value is expected for yesterday (GP posts the previous day after 05:25 local; the default `expectedLatestDay`).
- **Missing values.** `998877` (a number) is dropped, as are `MISSING`, `NO RECORD`, blank cells and values <= 0. Quality flags are not requested (`flags=false` on PN, `format=2` on GP).
- **Datum.** Reclamation reports in the project datum and does not state it per series. The binding review records it and sets `datumOffsetFt` (live) / `offsetFt` (history) when it differs from the lake's pool reference.
- **Health plane.** `hydromet` is not yet a declared Lake input (`brain.json` providers, `providers/PROVIDERS.json`, the `lake-brain` job manifest, Swift `BrainOwnership`) and has no source-health record in `LakeBrainRunner.sourceRecords`; that registration belongs with the first accepted Hydromet binding (operating contract section 10).
- **Access note.** usbr.gov's `robots.txt` disallows automated fetching of `/pn-bin/` and `/gp-bin/` (a fetch tool was refused on that ground on 2026-11-22). The Brain is not a crawler (it requests named series only, a few requests per lake per run, and identifies itself), but the owner should confirm this use, or ask Reclamation, before a lake is bound.
- **Tests.** `brains/lake/tests/swift/LakeBrainHydrometTests.swift` with `brains/lake/tests/fixtures/hydromet/` (PN instant CSV, GP daily and instant inside HTML with `BEGIN DATA`, each with a `998877` row). The fixtures were assembled from the documented formats because usbr.gov was not reachable from the authoring session; replace them with recorded answers on the first live probe, and correct the PN header shape there if it differs. No test makes a network call.

### NWRFC (Northwest River Forecast Center): not implemented
NWRFC publishes observed pool heights for some reservoirs on HTML station pages (`nwrfc.noaa.gov/station/flowplot/textPlot.cgi?id={LID}&pe=HP`, `hydroPlot.php?id=…&showdata=1`), labelled "Observed" and separate from forecast tables. It was not built: there is no documented machine-readable API or terms for these pages, the text page states no unit and only a fixed-PST stamp, and in one probe on 2026-11-22 a request for one station id returned another station's table, an identity risk a binding must never carry. The observed series behind it is the NWS DCP stream, which the Engine already reads through `nwps` (live) and IEM HADS (history) under the same NWS location id. The one research lake on NWRFC (Lake Cushman|WA, excluded as `provider-not-allowed` and post-hoc) should be re-probed against NWPS / HADS for its NWS location id instead.

### USACE Northwestern Division CWMS offices (NWDP / NWDM): no change needed
The CWMS reader sends the binding's `station` as the CDA `office` parameter unchanged (`PublicLakeLevelFeeds.cwms`, `cwmsLevel` / `cwmsSeries` operator levels and the dry-run checker do the same), so a series published under a division office id (`NWDP` Northwestern Division Pacific, `NWDM` Northwestern Division Missouri) is read exactly like a district's. Reviewed bindings already do this: Moses Lake|WA, Lake Chelan|WA, Lake Pend Oreille|ID, Coeur d'Alene|ID, Fern Ridge Reservoir|OR, Flathead Lake|MT and Hungry Horse Reservoir|MT on `NWDP`, Lake Oahe|SD and Branched Oak Lake|NE on `NWDM` (`LakeBrainHydrometTests.testDivisionOfficeIsPassedThroughToCWMS`, `testReviewedBindingsAlreadyReadDivisionOffices`). A research row labelled `cwms-nwdp` (Lake Roosevelt (FDR)|WA) is excluded by the bindings-table allow-list and as a post-hoc row, not by the reader; admitting it is a binding decision for the acceptance gate, mapped like `cwms-saw` (provider `cwms`, station = the office).
