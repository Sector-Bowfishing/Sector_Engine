# LGC-2026-11-23.5 is superseded

`LGC-2026-11-23.5.rules.json` (sha256 befcc41dece500688e4c6062372c54e4907aa288d4cad44c38a2ce0b131e23de) is kept byte for byte. It
was **never used**: no census request was sent under it. It is superseded by
[`LGC-2026-11-23.6.rules.json`](LGC-2026-11-23.6.rules.json), registered alone in its own commit before the code changed, after the
round-5 review of PR #247 on 2026-11-23, which found, before any request was sent:

- the research folder was chosen freely on the command line and the ledger was only self-anchored, so the census could be run in
  several folders and the best result posted. Now the run is bound to the shared run ledger (`tools/research/protocol_run_ledger.py`,
  #251) at the root that Cortex `research-path` returns for lake-brain, and no step (controls included) runs before this ledger's
  `Run anchor:` is the earliest one for the rules id on Sector_Ops #51; the census posts `Run start:` and `Run result:` records there;
- `.5` let a run that had started writing end FAILED and let an aborted run be retried with `--skip-controls`. Now a STARTED attempt
  with no end is terminal, an interrupt after any request is a failure (never an abort), `--skip-controls` is gone, and recovery is a
  new rules id with revised rules that record the #51 human review;
- `.5` still said "local files in --out" in `publication.output` and named run folders `run-<N>/`.

The tool refuses this file, like `.4`, `.3`, `.2` and the first registration: it loads only `LGC-2026-11-23.6`.
