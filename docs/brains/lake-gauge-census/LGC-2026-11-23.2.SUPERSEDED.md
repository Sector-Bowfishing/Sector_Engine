# LGC-2026-11-23.2 is superseded

`LGC-2026-11-23.2.rules.json` (sha256 c17feef35f03c072cb79f4d318b465d807fc72afe5ca351f0b787cc3df382ba7) is kept byte for byte. It
was **never used**: no census request was sent under it. It is superseded by
[`LGC-2026-11-23.3.rules.json`](LGC-2026-11-23.3.rules.json) after the round-2 review of PR #247 on 2026-11-23, which found, before
any request was sent:

- the origin border covered only USGS/USACE: an unlabelled CWMS series (for example `Raw-USBR` read as unlabelled, or a CWMS copy of a
  Reclamation reservoir) never overlapped USBR, so it could come out INDEPENDENT_AGENCY against a bound RISE item. Now an unlabelled
  CWMS series is origin-unknown against every other agency, and USBR / CDEC labels in a CWMS version are parsed as copies;
- a failed CWMS office location catalog was cached as empty for the whole run, so its lakes looked like "no candidate";
- lakes left undiscovered by an exhausted budget were counted as "no candidate";
- the USGS future-time tolerance in the code (+1 day + 1 h) did not match the registered text;
- robots.txt 429 allowed fetching.

The tool refuses this file: it loads only the current rules id.
