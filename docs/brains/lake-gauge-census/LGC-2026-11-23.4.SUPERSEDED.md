# LGC-2026-11-23.4 is superseded

`LGC-2026-11-23.4.rules.json` (sha256 64ca297f43331893dd70a15edcc5a84fd76721c434c042cc67c381b616f41494) is kept byte for byte. It
was **never used**: no census request was sent under it. It is superseded by
[`LGC-2026-11-23.5.rules.json`](LGC-2026-11-23.5.rules.json), registered alone in its own commit before the code changed, after the
round-4 review of PR #247 on 2026-11-23, which found, before any request was sent:

- no run binding: a second `--out` folder could re-run the census and pick the better result, and arguments, registry source,
  geometry and cache were not recorded. Now one hash-chained ledger per rules id in the research folder; only census run #1 counts;
  outputs are write-once; `--lakes`, `--registry` and `--usgs-api` are fixed; `--skip-controls` needs an aborted earlier attempt
  with passing controls;
- origin evidence was not registered: now its sha256 must be in the rules or a ledger line written before census run #1, the output
  records its hash and text, and evidence for an already-labelled series is refused;
- RISE_UNCONFIRMED was only checked against USGS: now it is origin-unknown against every family;
- a failed outline or registry read left the lake looking like "no candidate": now GEOMETRY_UNAVAILABLE;
- the OGC fallback ignored next links, a WaterServices 404 always counted as empty, derived versions matched whole words only, base
  locations were compared case-sensitively, and rows or locations without coordinates were dropped silently.

The tool refuses this file, like `.3`, `.2` and the first registration: it loads only `LGC-2026-11-23.5`.
