# LGC-2026-11-23.3 is superseded

`LGC-2026-11-23.3.rules.json` (sha256 2a46ac96df8021c5fca08d19406f5e60eedd19e266289f9130515ecb76b5b8b1) is kept byte for byte. It
was **never used**: no census request was sent under it. It is superseded by
[`LGC-2026-11-23.4.rules.json`](LGC-2026-11-23.4.rules.json), registered alone in its own commit before the code changed, after the
round-3 review of PR #247 on 2026-11-23, which found, before any request was sent:

- two unlabelled CWMS series at least 1 km apart could be INDEPENDENT_SITE, although both can derive from one upstream sensor and CWMS
  location coordinates are not sensor coordinates. Now any pair with an unlabelled CWMS series on either side is UNCERTAIN without
  reviewed origin evidence;
- CWMS series were compared by full location id, so `Kinzua-Lake` and `Kinzua-Tailwater` or `Kinzua` looked different. Now the base
  location (before the first `-`) is compared, and derived versions (Best, Rev, Comp, Calc, CCP) are derivations;
- RISE items were always USBR, although RISE republishes USGS data. Now a RISE item is USBR only when its own metadata names
  Reclamation;
- several discovery failures (RISE catalog or item, CWMS time-series catalog, USGS time-series metadata, a provider disabled by a
  failed control, an oversize USGS box, a pagination cap) left a lake looking like "no candidate". Now each marks the lake incomplete.

The tool refuses this file, like `.2` and the first registration: it loads only `LGC-2026-11-23.4`.
