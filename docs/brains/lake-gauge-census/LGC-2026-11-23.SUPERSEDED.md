# LGC-2026-11-23 is superseded

`LGC-2026-11-23.rules.json` (sha256 254752ea31823ace94768a7daa658cf70bfa42b8ad0d276ebb1cae1cf86e9e3f) is kept byte for byte as the
first registration. It was **never used**: no census request was sent under it. It is superseded by
[`LGC-2026-11-23.2.rules.json`](LGC-2026-11-23.2.rules.json) after the review of PR #247 on 2026-11-23, which found, before any
request was sent:

- the date guard covered only `census`, not `controls` or the geometry fetch (now in the fetcher; `notBefore` 2026-12-01T12:00Z);
- an unlabelled CWMS series could be called independent of a USGS gauge although USACE districts publish USGS-operated gauges
  under their own version names (now UNCERTAIN unless an origin-evidence entry says otherwise);
- rule-curve cues were incomplete and a future latest time was not treated as a plan series;
- robots.txt 5xx/unreachable allowed fetching (RFC 9309 says disallow), redirects were followed, retries were not counted;
- one failed chunk could stop the whole run without output.

The tool refuses the old file: it loads only the current rules id.
